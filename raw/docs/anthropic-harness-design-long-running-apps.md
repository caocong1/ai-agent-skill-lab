## 问题定义

作者要解决两个相互纠缠的问题：让 Claude 产出高质量的前端设计，以及让它自主地在长时间会话里构建完整应用。文中的判断是：单纯的 prompt engineering 和基础 harness 设计各自都会**碰到天花板**，需要换一种结构。

## GAN 式的生成器 / 评估器分离

设计灵感来自生成对抗网络：让**生成**与**评估**由不同 agent 承担。动机是一个具体的失败模式——让 agent 评估自己的产出时，它倾向于**自信地夸奖自己的工作**，即使在人类看来质量明显平庸。分开之后，生成器可以宽松，评估器可以苛刻。

全栈编码场景把它扩展成三个角色：

- **Planner**：把 1–4 句的简短需求展开成详细的产品规格。文中强调 planner 应聚焦**产品语境与高层技术设计**，而不是细节实现，以避免规格层的错误级联放大。
- **Generator**：按 sprint 分解实现功能，交付前先自评。示例技术栈为 React、Vite、FastAPI、SQLite/PostgreSQL。
- **Evaluator**：通过 Playwright MCP 驱动真实运行中的应用，模拟用户操作，对照具体标准评分并在交付前找出 bug。

评估器的调优方式被明确写出：**读评估器的日志，找出它的判断与作者判断分歧的样例，然后更新 QA prompt 去解决这些分歧**。

## Sprint contract 与基于文件的交接

每个 sprint 开始前，生成器与评估器先协商一份 **sprint contract**，定义交付物与成功标准。两个 agent 通过**文件**顺序读写来沟通与修订，作者的说法是这样"让工作忠于规格，同时避免过早把实现细节写死"。它在高层用户故事与可测试实现之间架桥，而不提前锁定技术方案。

## Context anxiety 与 context reset

- **Context anxiety**：Sonnet 4.5 表现出一种倾向——当模型接近它感知到的 context 上限时，会**提前草草收尾**。
- **Context reset vs compaction**：harness 采用的是**完全清空**会话历史的 context reset，而不是摘要式 compaction。理由是 compaction 虽然保留连续性，但"不给 agent 一块干净的白板，所以 context anxiety 仍然会存在"。reset 需要**结构化的交接产物**来承载前一个 agent 的状态，但能彻底消除这种焦虑。
- **假设过期**：Opus 4.5 基本上自己消除了 context anxiety，于是 context reset 从更新后的 harness 里被**整个删掉**。

## 让主观质量可评分

为把前端审美变成可评分对象，作者定义了四条标准：

- **Design Quality**：颜色、排版、布局、图像的整体一致性。
- **Originality**：自定义决策 vs 模板默认值，并明确点名"白卡片上的紫色渐变"这类 AI 生成痕迹。
- **Craft**：排版层级、间距、色彩和谐、对比度。
- **Functionality**：独立于美观的可用性。

评估器用 Playwright 打开真实页面、截图，然后再评分。作者用**带详细分数拆解的 few-shot 样例**校准评估器，使其判断贴近自己的偏好，并**减少迭代之间的分数漂移**。

评估器的产出是颗粒化、可执行的，例如："矩形填充工具应支持拖拽填充选中区域 —— **FAIL** —— 工具只在拖拽起点和终点放置了瓦片，没有填充区域。"

## 迭代不是单调上升

作者观察到：分数总体随迭代改善，但**并不总是线性**；后期实现整体更好，但他经常更偏爱某个中间迭代版本，而不是最后一版。

## 明确写出的工程规则与失败模式

1. **自评不可信**：agent 会过度夸奖自己的产出，因此外部评估是必要的。
2. **分解仍然重要**：把复杂任务切成可处理的块，是长会话里保持连贯的前提。
3. **假设会过期**：*"harness 里的每一个组件，都编码了一条关于模型自己做不到什么的假设，而这些假设值得被压力测试……因为随着模型进步，它们会很快过时。"*
4. **评估器的性价比取决于任务难度相对模型能力的位置**：任务在模型能力之内时，评估器只是额外开销；任务处于边缘时，它能抓住"最后一公里"的问题。
5. **措辞会塑造产出**：标准的用词会以作者没有完全预料到的方式引导生成器——例如加入"最好的设计是博物馆级的"这类表述，会把设计推向某种特定的视觉收敛。

## 模型演进带来的 harness 简化

Opus 4.6 规划更谨慎、能维持更长的 agentic 任务、处理更大的代码库，这让作者**整个删掉了 sprint 这一构造**——生成器可以在 2 小时以上的构建里自己保持连贯。评估器在直接任务上的必要性下降，但仍然能捕捉边缘情况与缺失功能。

## 成本数据

- 单人 20 分钟构建：约 $9。
- 完整 harness：约 6 小时、$200+，但产出的应用明显更完整、bug 更少。
- 后期的 DAW 案例：3.8 小时、$124.70。

作者的立场是这仍然昂贵，但能力上确实更强。
