# Claude Code Auto Mode 分析：统计分类器如何与机械权限边界分层

> 分析版本：1.0 ｜ 最后更新：2026-10-25 ｜ 来源：Anthropic《How we built Claude Code auto mode: a safer way to skip permissions》（发布 2026-03-25，抓取 2026-10-25）｜ 快照：`raw/docs/anthropic-claude-code-auto-mode.md`

本仓库已有的权限结论都是**机械的**：DeepSeek Harness 的单调 `ToolGuard`（返回类型不表达 allow，监听器顺序无法重开权限）、`ApprovalOutcome` 闭合四元组（unavailable ≠ allowed）、恢复时不继承序列化授权。这些机制精确但昂贵——每一步危险动作都要一个人类决策。本文回答的是下一个问题：**当人类对 93% 的审批提示直接放行时，"每步审批"已经名存实亡，统计分类器能不能顶上这一层**。

Anthropic 的答案是一个分层系统：机械边界继续管"什么绝对不行"（白名单、信任边界、block 规则），分类器接管"机械规则覆盖不了的语义判断"（意图与爆炸半径的匹配），人类只接收熔断升级。这与 07 综合里"权限在工具执行边界"不冲突——分类器仍然在执行边界上运行，只是判定者从人换成了模型，且这个判定者本身被机械规则约束（reasoning-blind、deny 预算）。

这个形状此后在本仓库的另外两个本地 harness 来源里独立出现：OpenAI Codex 的 Guardian（策略与人之间的模型审批层，带连续拒绝与窗口拒绝两道熔断，见 `analysis/16-openai-codex-harness.md`）与 DeepSeek Harness 0.2 的实验性 Auto review（见 `analysis/18-deepseek-harness.md`）。三家互不依赖地收敛到"机械边界之上加一层模型审批、熔断回人"，这是本文结论的外部印证；而 DeepSeek 自陈的绕过缺口（程序化工具调用里的直接副作用不经审查）给出了这一层最容易漏的地方。三家在**判定上下文**上并不一致：本文的分类器只看用户消息与裸工具调用；Codex 的 Guardian 恰好相反，看的是带来源标注的完整记录，还能在只读、无网络的子会话里调查，但没有公布误判率。本文的输入消融是反对后者的证据，却没有测过"完整记录 + 来源标注 + 只读调查"这个组合，所以这里不判定孰优，只记下两者共同的硬约束：只有用户或开发者来源的内容能构成授权，审查失败一律按拒绝处理。

## 核心抽象

- **审批疲劳是安全参数**：93% 放行率意味着人工审批这道防线的有效性趋近于零。安全设计必须把"人的注意力是有限资源"当作输入，而不是当作可以无限索取的输出。
- **两层防御**：输入层在工具输出进入上下文前做注入探针（防线的上游）；输出层在动作执行前做 transcript 分类器（防线的下游）。两端夹住中间的"模型推理"，各自独立失效不联动。
- **三级权限流**：Tier 1 安全白名单 + **进入 auto mode 时收回任意执行的 blanket 规则**；Tier 2 项目内文件写跳过分类器（交给版本控制审查）；Tier 3 shell/web/subagent/项目外全走分类器。分级的原则是**按"错误的可发现性"分级**——可被 git diff 审查的错误不需要分类器，不可逆的错误才需要。
- **Reasoning-blind 分类器**：只看用户消息 + 裸工具调用，剥掉 assistant 文字、工具输出与工具调用描述。一个设计同时解决两个问题：执行 agent 无法说服判定者（没有可以说服它的材料），注入攻击无法进入判定上下文（没有注入的入口）。这不是只凭推理得出的：原文做了输入消融——加入 assistant 文字与工具结果后效果变差；只给工具调用漏判最低，却丢了用户意图这个锚。判定上下文的取舍因此是一个被测出来的结果，而不是一条风格偏好。

## 重要模式

### "收回 blanket 规则"是分级审批的前置动作

进入 auto mode 时把"任意 shell/解释器/包管理器"类 blanket 规则撤销，让危险命令**重新可见**于分类器。这是本仓库已有教训（工具自述不是授权依据、聚合配置会掩盖可执行面）的一个精确实例：**权限聚合层的存在会系统性遮蔽下游判定者的视野**。任何"信任模式切换"都要重新评估既有规则的遮蔽效应。

### deny-and-continue：拒绝是工具结果，不是终止

拒绝以工具结果返回，语义是"善意对待边界、另寻安全路径"。这保留了 agent 的自主性（换路径完成合法目标），又不松动边界本身。兜底是**deny 预算**：连续 3 次或累计 20 次拒绝后熔断给人工——预算是机械的，判定是统计的，**统计层永远被机械层兜底**。

### 用错误分类数据诚实标定能力边界

0.4% FPR（真实流量）、17% FNR（真实过度激进集）、5.7% FNR（合成外泄集），并把漏判归因写明：**分类器看得出危险，但误判"同意是否覆盖该动作的爆炸半径"**。作者的结论同样诚实：相对 skip-permissions 是改善，相对认真人工审查可能是退步，auto mode 不是高风险基础设施上人工判断的替代。本仓库应把"发布安全机制时同时发布其 FPR/FNR 与失效模式"当作可模仿的披露范式。

### 主要漏判来自"同意范围"误判，而不是看不出危险

设计规则是默认按意图拒绝：agent 自主选择的一切都未经授权，除非用户明说；一个问题不是指令；"清理我的分支"不授权批量远程删除。授权匹配是**逐动作**的，匹配的是动作的爆炸半径而非表面动词。

但 17% 的漏判说明这条规则很难被一个模型判定者执行到位：分类器通常**看得出动作危险**，问题出在它找到一段"看起来像授权"的话就停下，没去核对这份同意是否覆盖眼前这个动作的爆炸半径（"清理这个 PR"并没有说可以 force-push）。原文明说提示词工程没能修好它。（2026-09-04 草稿把这一点写成了"不得把一次既往审批当作模式"的设计规则——那是误读，原文描述的是失败模式。）

推论：模型审批层最弱的环节是"同意范围"这个语义判断，所以它必须被机械边界兜底，而不能被当作授权的最终来源；若要改善，比改提示词更可靠的方向是让用户的同意本身带上范围（针对哪个对象、允许到什么程度），给判定者一个可核对的东西。

### 多 agent 交接的不对称处理

subagent 委派时可拒绝（下行有真实风险），返回时只警告（上行丢弃成果的代价是浪费已完成的合法工作）。**下行用 deny、上行用 warn** 是一个可复用的不对称原则：风险不对称时，闸门的松紧也应该不对称。

## 工程启发

- **机械边界与统计分类器的分层表述**：单调 guard / 闭合审批集管"不可重开的硬边界"；分类器管"语义正确但需要判断的灰区"；人类只在 deny 预算熔断时出现。三层各自独立失效：分类器失效 → 熔断回人工；机械边界失效 → 无论如何都挡不住（所以机械边界永远不能依赖分类器补强）。
- **评审/判定上下文要最小化**（reasoning-blind）：任何"由另一个模型做判定"的组件（审批分类器、evaluator、code reviewer）都应该只拿到判定所需的最小上下文。判定者看到的执行过程越少，被执行者说服的面越小。这与 `analysis/19` 的 generator/evaluator 分离同构：分离的不只是模型实例，还有**输入流**。
- **进入高自治模式时的规则重估**：模式切换（手动 → auto、dev → prod、单人 → 团队）必须伴随一次"既有授权规则的遮蔽审计"。
- **两阶段分类器是成本设计**：单 token 快筛 + flagged 才 CoT + 第二段 prompt cache 命中，把"每个动作都过一个大模型"的成本压到"每个动作过一个小模型 + 少数动作过大模型"。任何高频模型闸门都可以套这个形状。
- **deny-and-continue 需要 deny 预算**：无预算的"拒绝后重试"就是无限循环的配方（与 07 综合"每层 loop 都要有预算"一致，这里把预算对象从"步数"换成了"拒绝数"）。

## 适用场景

- 高频工具调用、人工审批不可扩展的 agent（CI 里的自治 agent、内嵌产品的 agent）。
- 已有机械边界（白名单/沙箱/guard），需要在此基础上加一层语义判定的系统。
- **不适合**：低频高危操作（每步人工审批仍然是对的选择）；没有可靠 block 规则与信任边界定义的系统（分类器没有可兜底的东西）；把分类器当唯一防线（17% FNR 明确反对这一点）。

## 注意

- 数字来自 Anthropic 的内部数据集（n=10,000 / 52 / 1,000），"真实过度激进集"只有 52 条，FNR 置信区间宽。
- 分类器跑在 Sonnet 4.6 上——**它自身是"带日期的假设"**：换更强模型时要重测 FPR/FNR，也要防更强的执行 agent 更会绕过弱判定模型。
- 输入层探针只覆盖"进入上下文的工具输出"，模型自身生成的危险想法不在其覆盖范围（这是输出层存在的原因）。分类器针对"过度积极"与"诚实失误"调校，不是为失准模型设计的。
- Tier 2"项目内文件写跳过分类器"依赖 git 可审查这一前提；在没有版本控制的宿主环境里这个 tier 不能照抄。
- 发布后的数据（厂商自述，见快照文末）显示 auto mode 已成默认、宽泛 allow 规则被自动搁置、红队后漏判下降；同期也有第三方在小样本上报告 60–80% 的绕过率（诱导改用 curl、植入遮蔽标准库的文件）。两类数字都不足以单独定论，但方向一致：**模型审批层能显著减少人工打断，不能替代机械边界**。
- 审批本身是攻击面：一项 2026-10 的研究（arXiv 2610.22987，见 `analysis/26-durable-rules-production-evidence.md`）让仓库里的植入文本诱导 agent 去申请宽泛但看似合理的 allow 规则，一旦获批即可静默完成攻击。这说明"收回 blanket 规则"只解决了一半——agent 在任务中途**申请**新的宽泛规则，同样需要按爆炸半径审视。
