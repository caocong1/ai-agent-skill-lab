# Harness 组件的保质期：固定模型的效应、档位依赖、厂商删除与噪声底线

> 分析版本：1.0 ｜ 最后更新：2026-10-26 ｜ 覆盖来源：arXiv 论文 33 篇 + 厂商文章 / 文档 / changelog / PR / 源码 20 项（发布 2025-06 ~ 2026-10，抓取 2026-10-25）｜ 快照：`raw/docs/harness-shelf-life-research.md` ｜ 版本见 `analysis/SOURCE_INDEX.md`

`analysis/19-anthropic-harness-design-long-running-apps.md` 提出"每个 harness 组件都是关于模型做不到什么的带日期假设"，依据是 Anthropic 在 Opus 4.5 上删掉 context reset、在 Opus 4.6 上删掉 sprint；`analysis/21-lab-design-rethink-2026-08.md` 把它定为本仓库的组织原则——易腐组件（补模型的能力缺口）随模型变强而贬值，耐久组件（治理授权、证据、副作用、成本）反而增值——并写下了可证伪条件。`analysis/26-durable-rules-production-evidence.md` 收集了耐久那一半的证据。本文收集另一半：**哪些组件随模型变强而贬值、贬值的形状是什么、固定模型时 harness 效应到底多大，以及要怎样测才能把真实变化与噪声分开。** 文中以快照条目号（A1…F6）引用证据。

结论先行：**方向被证实，形状被否定。** 厂商确实在新代际亲手删掉了本仓库列为易腐的那类组件（C1、C4、C10、C11、C13），但研究给出的价值曲线不是"随模型变强单调下降"：它取决于模型档位、任务余量、窗口预算和具体的能力剖面（例如是否擅长 shell），常在中档最高，还会**换种类**——从准确率脚手架变成省钱工具（B1）。更要紧的是，固定模型时，多数 harness 改动对通过率的效应**落在测量噪声之内**（A3、A9、A10、F1），而厂商宣布删除时普遍不披露测量（C1 的"无可测损失"没有定义）；同一厂商的事故复盘显示，一行 prompt 就能让强模型退化并躲过发布前的评测（C3）。所以"保质期"在工程上可执行的部分，与其说是"升级就删"，不如说是**按档位、越过噪声底线去测；为此先有一张登记表，知道该测什么**。

范围（遵本仓库约定）：来源多为研究论文与厂商对自家 harness 的自述；Cursor、Replit、Amp、Claude Code、Codex 是产品，只取能迁移到自研本地 harness 的部分。

## 核心抽象

- **固定模型时，harness 对通过率的效应多数在噪声里，对成本的效应一贯很大。** 能力对齐的比较里，三个开源 harness 在两个模型上的通过率差不超过 8pp，且置信区间含 0（A3）；同一模型跑 Qwen Code 35 个连续版本，解决率在 23.0–39.0% 间摆动而与版本序无关，两次运行间 12.3% 的任务结果翻转（A9）；厂商自测 7 个版本、每版 500 题 × 3 次，均值极差只有 1.40pp（A10）。成本则不然：每个已解任务的 token 差约 41 倍（A3），同一任务跨脚手架的输入 token 中位数相差 5–28 倍（A4），版本间 token 涨 70% 而解决率无趋势（A9）。
- **大的通过率效应出现在 harness 改变"模型能接触到什么"时。** 给 shell 后前沿模型 +21.8 至 +24.5pp（A5）；输入超出窗口时把上下文放进环境、由模型写代码检视（A7）；只改沙箱资源配置就能移动 6pp（F2）。另一类大效应是模型 × 脚手架的交互：10 次重复下 Devstral-2 在两个脚手架上得 63.5 与 34.9，而 Qwen3-32B 方向相反（F1）——效应真实，但不能跨模型外推。
- **补偿组件的价值是模型档位的函数，并且会换种类。** 规划对 30B 模型是 +11.6pp 的准确率脚手架，对 550B 是 −2.0pp（不显著）却让每题便宜约 30% 的省钱工具（B1）；单 agent 基线越过约 45% 后，多 agent 协调的收益递减乃至为负（B4）；工程化 prompt 加调用图上下文，对最小模型 +86%、对前沿模型 +2%，后者在运行间噪声内（B5）。
- **而且不单调。** 屏蔽过期观察的收益呈平台—峰值—饱和的形状，同架构的新一代从 +11.7 降到 +3.7（B2）；harness 更新带来的收益在中档模型上最大（B3）；bash-only 的分界由 shell 熟练度而不是规模决定——同一处理让 Mistral 128B 在 SWE-bench 掉 23.2pp、在 Terminal-Bench 涨 6.7pp（B1）；组内最强的配置在遮蔽与摘要两种上下文管理下都显著掉分（A8）。
- **新代际也会要求新增组件。** Mastra 因 Claude 4.6+ 拒绝 assistant prefill、Gemini 3+ 拒绝以模型轮结尾的请求，新增了按代际开关的防护（C15）；OpenAI 的 Codex 指南删掉"让模型汇报前期计划"的提示，又为 gpt-5.3-codex 重新允许它，并要求重建历史时保留新增的 `phase` 字段，丢掉会"显著"降低性能（C16）。带日期的不只是补偿弱点的组件，也包括适配新约束的组件。
- **厂商删除的正是易腐类，保留的正是耐久类。** 删：system prompt 里的硬规则与强调措辞（C1 删 80% 以上，C11 删约 66%）、工具用法示例（C1）、todo / 计划工具的默认开启（C4、C10）、压缩后"多次压缩会降低准确率"的警告（C10）、handoff 与编辑回滚（C13）、鼓励派生 subagent 的指令（C11）。留：轮次与成本预算、写入闸门、挪进工具的校验与审批闸门、逐工具的权限检查（C6），以及"保留护栏"（C12）。
- **"验证"不是一个可以整体删除的组件。** 同一套厂商文档在 Opus 5 页要求删掉显式验证指令和"加独立验证步骤的旧式 harness 脚手架"，在 Fable 5 页又新增新上下文的 verifier subagent 与按工具结果审计进度声明（C5）。能按模型日程删的是"提示模型去自查"；不能删的是"完成判定与证据审计放在执行方之外"（`analysis/26`）。
- **Skills 与上下文文件：精选有益，但增益被高估、不可移植；自写的与堆叠的常常无益甚至有害。** 见下文专节。
- **自动 harness / skill 优化的增益大部分通不过公平评测**：同预算基线、留出集、复评方差三道关，见下文专节。
- **噪声底线比多数报告的效应大。** 温度 0 下同配置运行间 SD 仍有 1.0–1.8pp，80% 功效下检出 2pp 的差要 9–13 次运行（F1）；当前 Claude 前沿模型不接受非默认采样参数，"温度 0"这条控制手段已不存在（F6）。

## 重要模式

### 固定模型的 harness 效应：先看成本与翻转，再看均值

模型固定时，换 harness 对均值通过率的影响通常小于噪声，许多"harness X 让模型 Y 提高 N 倍"的标题经不起细读。SWE-Bench Mobile 的"同一模型跨 agent 差 6 倍"是单次运行下的 6/50 对 1/50（A1；快照按 Fisher 检验算得 p≈0.11，非原文）；Meta-Harness 在 TB2 上的对比基线取自公开榜单而非重跑，且 TB2 的搜索集就是报告集（A2）。

能稳定分辨的是三样东西：

1. **成本。** A3、A4、A9 的 token 差都是数量级的，置信区间不重叠。A3 作者的建议可以照搬：按 token / 延迟预算下的通过率选"harness–模型对"，任何模型比较都同时报告 token、延迟与完整 harness 规格。
2. **翻转的任务。** A9 两次运行间 12.3% 的任务翻转，与 16pp 的跨版本区间同量级；Anthropic 建议迁移时"不只看总分，看哪些任务翻转"（C6）。均值不变不等于行为不变。
3. **"能接触到什么"的改变**：shell（A5）、窗口之外的输入（A7）、沙箱资源（F2）。这类改动改变的是动作空间或资源，而不是告诉模型怎么想，效应因此大而稳定。

推论（本仓库的判断）：评估一个 harness 改动，先问它改变的是**模型能接触到什么**，还是只是**模型被告知什么**。前者值得期待通过率效应；后者在强模型上多半只剩成本效应，应按成本去测。

### 档位依赖：会下降，会换种类，也会倒 U

B1 是本批证据里最接近受控实验的一项：执行循环固定，只变规划、动作空间、上下文管理三个组件，配精确 McNemar 检验与 FDR 校正。它给出三条不同的曲线：

- **规划**的准确率价值随规模下降（30B +11.6pp → 550B −2.0pp），但在强模型上变成省钱工具（550B 成本约 −30%）。机制很具体：关掉规划时，30B 有 68.6% 的运行一行代码没改就结束（开规划时 27.8%）。
- **动作空间**的分界不随规模走：550B 用 bash-only 更好（+3.6pp），Mistral 128B 在 SWE-bench 上掉 23.2pp、在 Terminal-Bench 上反而涨 6.7pp，作者归因于 bash 熟练度。A5 在企业任务上给出同向证据（Opus 4.8 / GPT-5.5 用 bash 比只用 typed tools 高 21.8–24.5pp，在 bash 上再加 typed tools 无可测增益）；A6 则显示结构化低层接口让弱 actor 的重复一致性提高 4.7 倍，却给强 actor 增加 20% 输入 token。
- **上下文管理**的价值由窗口预算决定：受管与不受管之差随窗口从 32k 到 128k，从 35.7pp 降到 2.7pp（SWE-bench），主要是在防溢出；可召回的被删内容几乎没人用（64 个设置中 36 个从未调用召回工具）。

另两项给出倒 U：屏蔽过期观察（B2）在弱检索器下是 +6.2–6.6 的平台、中段峰值 +11.7、饱和格 −1.1 至 +3.8；harness 更新（B3）对中档开源模型收益最大（Qwen3-235B 在 SWE-bench 上 +19.3），对 Opus 4.6 只有 +2.6。多 agent 协调（B4）则是阈值形：单 agent 基线越过约 45% 后不再划算，且方向取决于任务结构（可分解的 Finance-Agent +80.8%，顺序的 PlanCraft −70.0%）。

推论：消融的单位不是"组件"，而是**组件 × 模型档位 ×（任务类别、窗口预算）**；结果要在**准确率与成本两个轴**上读。丢掉了准确率价值的组件可能还有成本价值，所以"升级就删"作为默认是错的，"升级就按部署档位重测、两轴都看"才对。B6、B7 从训练侧补了一个提醒：程序性 harness 可以被蒸馏进模型，蒸馏后再挂回去无益（B6）；微调过的模型离开训练所用的脚手架后，掉分远大于基座（B7）——模型与 harness 的耦合不只发生在推理侧。

三点判断：

1. **删除对象与本仓库的易腐清单高度重合，保留对象与耐久清单高度重合。** C6 与 C12 在折叠 subagent、放权给核心 loop 的同时，明确把预算、写入与审批闸门、权限检查留在 harness 或工具里。这是 `analysis/21` 条件一的方向性证实。
2. **Amp 的"默认不再请求许可"不是反例，而是对一种实现方式的否定。** 它的理由是：模型会写一次性脚本、串联 shell 命令，按工具名与参数做字符串匹配已无法静态判断后果，检查 `rm -rf` 只给人虚假的安全感。这说的是"字符串匹配不是边界"，与 `skills/secure-ai-agents/SKILL.md` 的"按动作的爆炸半径而不是表面动词匹配""先环境层后模型层"一致。本仓库不采纳"默认全放行"：自研本地 harness 若没有 OS 级隔离，默认全放行等于拆掉唯一的边界。
3. **措辞是易腐的，边界不是。** C8 指出，为旧模型写的强硬"先问我"措辞会让新模型在本该继续的地方停下。可迁移的教训是：把 prompt 层的权限**措辞**当易腐组件（随代际改写，并为安全工作流显式授权），把代码层的权限**执行**当耐久组件——即 `skills/build-ai-agents/SKILL.md` 的 "Prompt policy explains; code policy enforces"。

厂商证据的测量质量普遍偏低：C1 的"无可测损失"没有定义；C11 是线上 A/B 但不披露数值；C9 里"同一仓库快照、同一模型、只删或只改一条 AGENTS.md 指令，各重放一次再比较"的消融，只是文中**建议的提示词**，没有报告结果，且每条件一次本身就低于噪声底线。最有分量的反而是 C3 的事故复盘：三处 harness 改动造成用户感知的"模型变差"，其中一行字数限制"在我们跑的评测里无回归"，事后的逐行消融却在一个更广的评测上看到 Opus 4.6 与 4.7 都掉了 3%（未说明是百分点还是相对值）；补救是每次 system prompt 改动跑按模型的评测、模型特定的改动只对目标模型生效、牺牲智能的改动要 soak 期与渐进放量。**删除和新增一样需要按模型的评测**——否则"无可测损失"只说明评测没测到。

### 拆开"自查提示"与"独立判定"

C5 是同一厂商同一套文档里方向相反的两页：Opus 5 页说它不经要求就会自查，显式验证指令会导致过度验证，删掉可减少浪费且质量无损，"同样适用于加独立验证步骤的旧式 harness 脚手架"；Fable 5 页说新上下文的 verifier subagent 往往胜过自我批评，按实际工具结果审计进度声明"几乎消除了"捏造的状态报告。C6 把验证列为 subagent 仍然有效的用途之一；`analysis/19` 记录评估器只在任务处于能力边缘时才值得。

本仓库的读法：一个词盖住了两样东西。**"提示模型去验证"**是补偿弱点的 prompt 组件，易腐，强模型会自己做，留着就是过度验证。**"完成判定放在执行方之外、读执行方改不到的证据"**是耐久组件——`analysis/26` 的证据显示，执行方越强，自评越有说服力，独立判定越必要。Opus 5 页的"旧式脚手架"一句最容易被误读成"可以删掉独立判官"；它测的是平均质量与 token 浪费，不是长任务上的虚假完成。张力保留、不硬调和：对没有可验证终态、或虚假完成代价低的短任务，独立判官就是成本，可以按档位消融；对有可验证终态、虚假完成代价高的任务，不按模型日程删。

### Skills 与上下文文件：精选有益，自写无益，多了变差，对谁有益不可移植

- **精选 skill 平均有明显增益，但不均匀。** 18 个配置平均 +16.6pp（33.9% → 50.5%），配置间 +4.1 至 +25.7；绝对分最高的系统不一定获益最多；同一模型换 harness 差约 8pp（Opus 4.7 在 Claude Code 上 61.2、在 OpenHands 上 53.1）；87 题中 13 题为负增益（D1）。另一项研究里九个配置全部为正（+4.60 至 +19.54pp），但**同一组 skill 在 36.78% 的任务上对一部分配置有益、对另一部分有害**；且其 skill 组的提示明确要求使用 skill，无 skill 组没有（D5）。
- **对比"什么都不加"，增益可能不显著。** skill 比原始条件只高 +2.84pp，CI [−2.27, +7.95]；比 workflow memory 高 +6.06pp，显著。机制标签里"程序性锚定"占 65.7%，"显式知识注入"只占 4.5%（LLM 判定的标签）；候选池从 5 扩到 100 时，实际使用的 skill 中属于正确集合的比例从 29.6% 降到 3.3%，成功率却没有下降（D3）。
- **自写的有害，LLM 生成的上下文文件无益。** v4 中自生成 skill 在三个专用 harness 配置上全部低于无 skill（−8.1 至 −11.5pp），作者审计称其"最明显的赢处是泄漏而非复用"（D1）；LLM 生成的上下文文件不提高成功率（8 个设置中 5 个下降，不显著），成本却涨 20% / 23%（显著），开发者写的也只 +2.4%（不显著），而仓库概览并不减少到达首个相关文件的步数（D2）。
- **多了变差。** 每题 1 个 skill +18.0、2–3 个 +19.0、≥4 个 +10.1，"全面型" skill 只 +0.7（D1）；skill 过多时 Codex 会截短描述，描述互相矛盾会让模型加载无用指令（C8）；工具定义超过 30–50 个时选择质量下降（C6）。
- **怎样的修订有用。** 新增一条规则让"执行所需动作"率 +0.23、人工盲评的正确率 +0.10，收益主要来自点名旧 skill 没提到的命令或路径；按需加载正文只保留约 51% 的动作收益（D4）。输入输出契约清晰的 skill 交给 subagent 执行时胜过在上下文内执行，小模型胜得最多（D6，仅图）。
- **同预算下，记忆 / skill 模块不胜普通 actor。** 三个模型上普通 actor 的平均成功率都最高；作者还指出，单次运行的比较"能支持相反的标题"（D7）。

判断：skill 的价值真实存在，但**绑定在模型 × harness 上**（D1 Finding 2、D5 的 36.78%），"一个好 skill"不能跨配置假定有效。**谁写、依据什么写**决定方向：从执行证据里更新（B3、D4）有益，事前凭空写（D1 的自生成、D2 的 LLM 生成）无益甚至有害。本仓库本身就是一套 skill，这组证据直接适用于它自己（见 `analysis/21` 条件三）。

### 自动优化：同预算基线、留出集与复评方差三道关

- **同预算基线。** TB 2.1 上，无测试用例时 Harness Evolution 平均 67.4，不如直接运行 68.2 与并行采样 72.3；有测试用例时并行采样 82.0，Harness Evolution 69.7（E1）。
- **留出集。** E1 的留出增益为 +0.0。E2 覆盖 Meta-Harness、SkillOpt、AHE 三个框架：平均至少 54% 的增益归于过拟合、14% 归于额外的推理计算；排除 ALFWorld 后，15 个设置中 13 个的留出增益小于搜索集增益，4 个低于基线（E2 评测的 SkillOpt 是否就是 `analysis/13-skillopt.md` 分析的那个，待核验）。A2（Meta-Harness）与 E3（AHE）在 TB2 上都是搜索集 = 报告集。
- **复评方差。** ARC-AGI-3 上 27 条谱系两轮自我修订后，开发集 +8.42，留出集 +2.80，CI [−1.44, 7.35] 跨零；同一个 harness 复评 10 次的 SD 为 3.99——平均增益小于单个 harness 自己的复评波动（F5）。
- **唯一站得住的大胜**是有余量任务上的逐题搜索：E1 在 ARC-AGI-3 上相对同预算搜索基线 +79–81%。但那是逐任务的 test-time scaling，不是一个可复用的进化后 harness。
- **只追加、"不变差即接受"的循环会累积幻影护栏。** 针对从未发生的失败类别的护栏，在跨轮循环中从 1/60 升到 11/60，一旦进入就留下；要求"有据才接受"时为 0/60（E4，单一玩具实验室）。
- **两条正面的设计信号。** proposer 能读完整执行轨迹时候选中位 50.0，只看分数时 34.6（A2 Table 3，文本分类、每条件一次搜索）；更新者的能力影响很小（同一基准上最好与最差的更新者差 ≤3.1pp），执行者的能力影响大得多（B3）。

### 噪声底线与最小测量协议

- **运行间方差。** 60,000 条轨迹上，单次运行的 pass@1 随所选运行变动 2.2–6.0pp；温度 0 下 SD 1.0–1.8pp；80% 功效下检出 2pp 需 9 次（σ=1.5）至 13 次（σ=1.8），检出 1pp 需 36 次；轨迹的首次分叉总在前 1% 之内（F1）。
- **基础设施。** 同一模型、同一 harness、同一任务集，只改沙箱资源，Terminal-Bench 2.0 的成功率移动 6pp（p<0.01）。原文的意思是"低于 3pp 的榜单差距在评测配置被记录并对齐之前值得怀疑"，并把资源配置列为与 prompt 格式、温度同级的实验变量（F2）。
- **协议要素。** 每个 trial 从干净环境起步、按产出评分、读 transcript、capability 与 regression eval 分开、pass@k 与 pass^k 分开报（F3）；多数公开评测只能依赖单次运行，更高推理强度在 36 个组合中 21 个持平或更低，脚手架排名随模型家族翻转（F4）。

据此，本仓库采用的最小协议（写进 `skills/test-ai-agents/SKILL.md` 的 `## Comparing Variants Under Noise`）：每个任务多次 trial 并报离散；按任务配对，统计以任务而非种子为单位（McNemar、按任务重采样的 bootstrap）；先跑 A/A；同预算基线；留出任务；固定并记录资源配置、benchmark 版本与完整 harness 配置；pass@k 与 pass^k 分开报。不写死"每臂 N 次"：所需次数取决于方差与要检出的效应，按功效去算。

## 工程启发

- **先有登记表，再谈删除。** 每个补偿组件记一行"针对哪个模型的哪种行为"。deepagents 的按模型 profile 是现成样板：每条按模型键精确匹配并写明针对的行为，连"为什么这个模型不需要专属段落"也写在注释里（C14）。没有这张表，模型升级时只能对整个 harness 盲删，或像 C3 那样事后逐行消融。
- **按模型门控，回落方向按种类定。** 补偿弱点的组件对认不出的模型默认关（C4，见 `raw/docs/claude-agent-sdk.md`）；放宽权限的功能退回更严格的模式（`analysis/28-claude-agent-sdk.md`）；适配新接口约束的组件，Mastra 对认不出的 Anthropic 版本按不支持 prefill 处理（C15）。
- **删除和新增都要越过噪声底线。** 一行 prompt 就能让强模型退化并躲过发布前评测（C3）；厂商的"无可测损失"只说明它的评测没测到（C1）。
- **两个轴一起量：准确率与成本。** 规划在强模型上换成了成本价值（B1）；固定模型时，成本是最稳定的可分辨信号（A3、A4、A9）。
- **看翻转的任务，不只看均值**（C6、A9、D5）。
- **动作接口按模型选，并实测。** 擅长 shell 的模型给隔离良好的 shell，比大而全的 typed 目录分数更高也更省（A5、B1）；不擅长的模型没有 typed tools 会大幅掉分（B1）；给了 shell 就出现读评测脚本、读同事文件的 reward hacking，必须隔离（A5）；合规需要可枚举的工具面时，保留固定 typed 目录或只能调用它的程序模式（A5 的 PTC 建议）。这与 `analysis/17-mini-swe-agent.md` 的 bash-only 基线一致，并补上"按模型"这个条件。
- **历史要原样回放，包括厂商返回的元数据字段。** 重建历史时丢掉 `phase` 会显著降性能（C16）；打开"保留推理"与"压缩"两项上下文设置，让 GPT-5.6 Sol 在 ARC-AGI-3 上从 13.3% 到 38.3%（A11，C 级、评测细节未核验，见 `analysis/24-openai-codex-as-a-platform.md`）。推论：append-only 与原样回放不只省缓存，也关乎质量——与本轮写进 skill 的 append-only 规则同向。
- **给优化器完整轨迹，把模型能力花在执行者上，没有观察到的失败就不接受新增规则**（A2、B3、E4）。
- **上下文文件写 agent 否则会做错的指令（命令、约定、约束），不写仓库概览；skill 少而精，一个 skill 一个程序**（D1、D2、D4、C8）。
- **prompt 层的权限措辞随代际改写，代码层的权限执行不动**（C8、C13）。

## 适用场景

- **模型升级后的 harness 审查**：拿登记表按部署档位逐项消融，两个轴读结果，越过噪声底线再决定去留。
- **选 harness、比较 harness 版本、跟进开源 harness 的发布**：开源 harness 的发布速度超过每天 2 次（A9），版本间成本漂移常比分数漂移大；锁版本，按成本和翻转比较。
- **引入或修订 skill 与 `AGENTS.md` / `CLAUDE.md`**：从执行证据出发写，少而精，写指令不写概览，并在部署的模型 × harness 上实测。
- **采用自动优化工具**（SkillOpt、GEPA、ACE、Meta-Harness 一类）：先过同预算基线、留出集、复评方差三道关，再相信它的增益；`analysis/13-skillopt.md` 仍是设计参考，但其增益要按 E2 的归因去读。
- **决定拆多 agent 还是折回单 loop**：单 agent 越强，协调越不划算；可分解任务与顺序任务的结论相反（B4）；一次迁移一个 subagent，看哪些任务翻转（C6）。
- **不适用**：授权、证据、副作用、成本类组件的去留——见 `analysis/26-durable-rules-production-evidence.md`。本文的档位依赖结论不用于它们。

## 注意

- **证据分级要区别对待。** A 级（同行评审，或多模型受控并公开代码）给的是机制与可复现的数字；B 级多为单模型、单任务或无代码；C 级厂商自报一律没有完整测量（C1 无评测名与分数，C11 不披露 A/B 数值，C8、C13 无数值，C9 的 AGENTS.md 消融只是建议的提示词）。快照逐条标了级别。
- **模型覆盖是偏的。** B2、B3、D4、A9 多用开源或小模型；A 级研究里的"强模型"常是上一代前沿（Opus 4.x、GPT-5.x）；C 级厂商证据只覆盖各家自己的前沿模型。推到 Claude 5 / GPT-6 代要重测——A5 的作者自己就写了结论"可能不适用于后续版本"。
- **B1 每个组件只有一种实现，且每题单次运行**；它的曲线形状比具体数字更可信。
- **B8 不是"强模型不需要结构性防护"的证据。** CaMeL 式数据流隔离的效用代价总体随能力下降，但不单调（Fable 5 −20.5，大于 GPT-5.5 的 −8.0；Fable 5 还拒绝了 97 个良性任务中的 52 个）；GPT-5.5 在非自适应攻击下不加 CaMeL 的攻击成功率本来就是 0.0%，基准因此测不出它在顶端的价值。结构性保证防的是自适应攻击者，这个基准没测。它说明耐久组件的**代价**在变，不说明**保证**可以省。
- **冲突保留、不调和。** C5 的两页方向相反；2025 年 Anthropic 对 few-shot 示例"仍强烈建议"，2026 年对最新模型的**工具用法示例**明确反转（一般 few-shot 未提及），这是 C2 → C1 唯一明确的反转；Cognition 2025 → 2026 的立场修订只核验了标题与日期，正文待核验（C7）。
- **未能核验**：C7 两篇正文；E2 中的 SkillOpt 是否即 `analysis/13`；A11 原文正文；Meta-Harness 的 COLM 录用；2512.08296 的 v1 摘要；2608.11386 摘要数字的推导；C14、C15 读的是发布包而非钉住的 commit。快照末尾有完整清单。
- **本仓库自己仍没有验证集**，上面的最小协议还无法用于检验本仓库自己的 skill 改动（`analysis/21` 违反一）。本文带来的 skill 改动因此只是"按外部证据调整"，不是"本仓库测过有效"。
